Mo's Algorithm Xử lý truy vấn đoạn theo thứ tự √n

O(n√n) Time Complexity
O(n+q) Space
√n Block Size
Offline Mode

Mo's Algorithm biến một bài truy vấn đoạn O(n²) naive thành O(n√n) bằng cách sắp xếp thứ tự xử lý query một cách thông minh — giảm tổng số bước dịch chuyển con trỏ L, R xuống mức tối thiểu.

√N
01 — Động lực

Tại sao cần Mo's?

Xét bài toán cổ điển: Cho mảng A[1..n] và q truy vấn, mỗi truy vấn hỏi tổng / số phân biệt / gcd... trên đoạn [l, r].

O(n²) Brute force mỗi query
O(nq) Worst case tổng cộng
O(n√n) Mo's Algorithm ★
O(n log n) Segment Tree (nếu dùng được)

Segment Tree giải nhanh hơn, nhưng không phải bài nào cũng có thể merge — ví dụ đếm số phần tử phân biệt trên đoạn không có cấu trúc segment đơn giản. Mo's hoạt động với bất kỳ bài nào miễn là có thể add/remove phần tử trong O(1) hoặc O(log n).

⚡ Điều kiện áp dụng Mo's

1. Đọc được toàn bộ query trước khi trả lời (offline).
2. Có hàm add(x) và remove(x) cập nhật kết quả khi thêm/xóa phần tử x.
3. Query sau không phụ thuộc kết quả query trước (nếu có: dùng Mo 3D).

Vấn đề của brute force

Nếu xử lý query theo thứ tự input, với mỗi query mới ta phải reset và duyệt lại từ đầu. Tổng chi phí: tổng độ dài mỗi đoạn [l,r] — worst case O(n) mỗi query → O(nq).

🔴 Ví dụ tệ nhất

n = q = 10⁵. Queries: [1,n], [1,n-1], [1,n], [2,n], ... → Mỗi query dịch chuyển O(n) → Tổng 10¹⁰ thao tác. TLE ngay lập tức.

02 — Nguyên lý

Cơ chế Block Sort

Mo's chia mảng thành các block kích thước B = √n. Query được sắp xếp theo quy tắc:

📐 Quy tắc sắp xếp Mo

Bước 1: Sắp theo block(l) = l / B tăng dần.
Bước 2: Nếu cùng block: sắp theo r — block chẵn tăng, block lẻ giảm (tối ưu Hilbert).

// Mo blocks — mảng n=12, B=√12≈3

Tại sao O(n√n)?

  • L·R
    Phân tích di chuyển con trỏ R

    Trong mỗi block, R chỉ tăng hoặc giảm đơn điệu → tổng di chuyển ≤ n. Có √n block → R di chuyển ≤ n√n lần tổng cộng.

  • L·R
    Phân tích di chuyển con trỏ L

    Hai query liên tiếp trong cùng block: L thay đổi tối đa B = √n. Có q query → L di chuyển ≤ q·√n lần. Với q = O(n): O(n√n).

  • ∑
    Tổng = O(n√n) + O(n√n) = O(n√n)

    Với n = q = 10⁵ và B = √n ≈ 316: khoảng 3×10⁷ thao tác. Chạy trong ~1-2 giây với add/remove O(1).

  • ★
    Chọn B tối ưu

    Lý thuyết B = √n. Thực tế: B = max(1, (int)sqrt(n)) hoặc tune B = n/√q cho trường hợp n ≠ q. Tối ưu thêm với Hilbert curve ordering (~15% nhanh hơn).

04 — Implementation

Code C++ đầy đủ

mo_full_template.cpp 
// ════════════════════════════════════════════════
//  Mo's Algorithm — Template đầy đủ
//  Bài: Đếm số phần tử phân biệt trên đoạn [l,r]
//  Complexity: O((n + q) * sqrt(n))
// ════════════════════════════════════════════════
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 1e5 + 5;
int a[MAXN];           // mảng gốc (đã nén tọa độ nếu cần)
int cnt[MAXN];         // tần số phần tử trong cửa sổ hiện tại
int ans[MAXN];         // đáp án query thứ idx
int n, q, B;
int curAns = 0;        // đáp án đang theo dõi

struct Query {
    int l, r, idx;
};

// ── Thêm phần tử a[pos] vào cửa sổ ──
inline void add(int pos) {
    if (++cnt[a[pos]] == 1)
        ++curAns; // xuất hiện lần đầu
}

// ── Xóa phần tử a[pos] khỏi cửa sổ ──
inline void remove(int pos) {
    if (--cnt[a[pos]] == 0)
        --curAns; // biến mất hoàn toàn
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> n >> q;
    B = max(1, (int)sqrt(n)); // block size

    for (int i = 0; i < n; i++) cin >> a[i];

    vector<Query> queries(q);
    for (int i = 0; i < q; i++) {
        cin >> queries[i].l >> queries[i].r;
        queries[i].l--;              // chuyển về 0-indexed
        queries[i].r--;
        queries[i].idx = i;
    }

    // ── Sắp xếp Mo (với tối ưu block lẻ đảo chiều) ──
    sort(queries.begin(), queries.end(),
        [](const Query& a, const Query& b) {
            int ba = a.l / B, bb = b.l / B;
            if (ba != bb) return ba < bb;
            // block lẻ: r giảm → zig-zag, tiết kiệm di chuyển
            return (ba & 1) ? (a.r > b.r) : (a.r < b.r);
        });

    int curL = 0, curR = -1; // cửa sổ rỗng ban đầu

    for (const auto& qr : queries) {
        // Mở rộng / Thu hẹp cửa sổ về [qr.l, qr.r]
        while (curR < qr.r) add(++curR);   // R mở rộng sang phải
        while (curL > qr.l) add(--curL);   // L mở rộng sang trái
        while (curR > qr.r) remove(curR--); // R thu hẹp sang trái
        while (curL < qr.l) remove(curL++); // L thu hẹp sang phải

        ans[qr.idx] = curAns;
    }

    for (int i = 0; i < q; i++)
        cout << ans[i] << '\n';
    return 0;
}

Chú ý thứ tự add/remove

⚠️ Thứ tự 4 vòng while

Mở rộng trước, thu hẹp sau. Cụ thể: mở R → mở L → đóng R → đóng L. Nếu đóng trước mở, cửa sổ có thể rỗng tạm thời → kết quả sai. Thứ tự trên luôn đúng.

05 — Biến thể

Các dạng Mo mở rộng

01

Mo's with Update

Có cả update điểm và range query. Thêm chiều thứ 3: thời gian (timestamp). Sắp query theo (block[l], block[r], t). Cần thêm hàm apply/undo update.

O(n^(5/3))
02

Mo's on Tree

Query trên đường đi giữa hai đỉnh u, v. Flatten cây bằng Euler tour, xử lý như query đoạn 1D. Lưu ý: node xuất hiện chẵn lần = không tính.

O(n√n)
03

Rollback Mo (Undo Mo)

Khi remove khó (ngược chiều mở rộng), dùng checkpoint + rollback: chỉ mở rộng R, dùng stack undo cho L. Hiệu quả với bài linear basis, union-find.

O(n√n)
04

Hilbert Mo

Sắp query theo đường Hilbert curve thay vì block. Giảm ~30% số bước thực tế so với Mo chuẩn. Implement bằng hàm tính Hilbert index O(1).

~30% nhanh hơn

Mo's with Update — Cấu trúc query

mo_update.cpp 
// Mo's Algorithm với Update (Mo 3D)
// Complexity: O(n^(5/3))
// Block size tối ưu: B = cbrt(n * max(n, q) * 2)
#include <bits/stdc++.h>
using namespace std;

int B; // block size = n^(2/3)

struct Query {
    int l, r, t; // t = số update đã xảy ra trước query này
    int idx;
};

struct Update {
    int pos, oldVal, newVal;
};

// Sắp xếp 3D: (block[l], block[r], t)
auto cmp = [](const Query& a, const Query& b) {
    int ba = a.l/B, bb = b.l/B;
    int ra = a.r/B, rb = b.r/B;
    if (ba != bb) return ba < bb;
    if (ra != rb) return (ba & 1) ? ra > rb : ra < rb;
    return (ra & 1) ? a.t > b.t : a.t < b.t;
};

void applyUpdate(Update& u, int curL, int curR, int* a) {
    // Nếu update nằm trong cửa sổ: remove cũ, add mới
    if (u.pos >= curL && u.pos <= curR) {
        remove(u.pos);
        a[u.pos] = u.newVal;
        add(u.pos);
    } else {
        a[u.pos] = u.newVal;
    }
}
// undoUpdate: tương tự nhưng dùng oldVal

Mo's on Tree — Euler tour trick

mo_on_tree.cpp 
// Mo's on Tree — query đường đi u→v
// Euler tour: mỗi node xuất hiện 2 lần (in + out)
// Node xuất hiện chẵn lần trong window → KHÔNG tính

int tin[MAXN], tout[MAXN], euler[2*MAXN];
int timer = 0;
bool inWindow[MAXN];

void dfs(int u, int p) {
    euler[timer] = u;
    tin[u] = timer++;
    for (int v : adj[u])
        if (v != p) dfs(v, u);
    euler[timer] = u;
    tout[u] = timer++;
}

// Query (u, v): nếu tin[u] > tin[v], swap
// l = tout[u], r = tin[v]   (nếu u là tổ tiên của v)
// l = tin[u],  r = tin[v] + 1 còn thêm lca(u,v)

void toggle(int node) {
    if (inWindow[node]) {
        remove(node);        // node xuất hiện lần 2 → xóa
        inWindow[node] = false;
    } else {
        add(node);           // node xuất hiện lần 1 → thêm
        inWindow[node] = true;
    }
}
// Trong vòng xử lý: thay add/remove bằng toggle(euler[i])

📊 Khi nào Mo's tốt nhất?

Không thể merge (gcd, xor basis, đếm phân biệt phức tạp) → Mo's là lựa chọn hàng đầu.
add/remove O(1) → Mo's rất nhanh trong thực tế (~10⁷–10⁸ ops/s).
n, q ≤ 10⁵ → n√n ≈ 3×10⁷. Vừa đủ 1-2 giây. Nếu n = 10⁶ → 10⁹ → TLE.

Ứng dụng thực tế

🎨 Đếm màu phân biệt [l,r]
🔢 Tổng bình phương tần số
📐 GCD của đoạn
⚡ XOR Linear Basis [l,r]
🌳 Mo's on Tree (subtree/path)
📊 Số cặp (i,j) a[i]=a[j]
🔤 Lexicographically smallest
💎 CF: Powerful Array, Sherlock
🏆 Tips tối ưu thực chiến

1. Hilbert ordering: thay block sort bằng Hilbert index, nhanh hơn ~20-30%.
2. B tùy chỉnh: nếu add/remove O(log n), dùng B = n/√(q·log n) để cân bằng.
3. Coordinate compression: nén giá trị về [0, m) trước để cnt[] nhỏ hơn.
4. inline: thêm __attribute__((optimize("O3"))) và inline vào add/remove.
5. Tránh swap: sắp xếp query đúng hướng từ đầu, không swap l/r runtime.
